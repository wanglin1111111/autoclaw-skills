# 分布式社区建设与治理工作环境

> 基于《706青年社区报告 2012-2026》封装的可复用技能。
> 本技能是覆盖从社区价值观、组织架构、节点建设、治理机制到活动组织和知识沉淀的完整社区建设工作环境，帮助用户建立分布式社区的设计思维和运营能力。

---

## 1. 任务边界

**做**
- 提供分布式社区建设的完整方法论：从价值观到组织架构到落地执行
- 帮助用户理解"六共"价值观体系（共居/共享/共学/共玩/共建/共创）及其实践方式
- 指导社区组织架构设计：节点自治 + 支持中心协同 + 大会共识 + 轻量治理
- 提供三种节点形态（城市客厅/流动客厅/生活实验室）的选址和运营指导
- 指导社区治理机制设计：权限逻辑、反馈问责、公共基金管理
- 提供社区活动组织全流程（从发起到沉淀）
- 指导社区知识库建设和经验沉淀方法论
- 帮助用户设计包容性与多元共生的社区规则
- 提供个人/团队在社区中的成长路径设计
- 帮助理解"小中心、大网络"的分布式组织运作逻辑

**不做**
- 不提供具体场地的租赁、装修和合规审批指导
- 不代替用户制定具体的社区财务预算和会计方案
- 不涉及法律主体的注册、税务和劳动关系问题
- 不提供社区安全事件的应急响应预案（提供框架，具体需专业支持）
- 不做社区商业化的完整商业计划书

## 2. 社区发展模型

### 2.1 706 社区发展历程（2012-2026）

| 阶段 | 时间 | 特征 | 关键转折 |
|------|------|------|---------|
| 起源期 | 2012 | 北京单一中心空间，青年公共空间 | 围绕公共讨论、跨文化交流与生活方式实验 |
| 转型期 | 2017-2019 | 从"单一中心空间"转向"社群化、多节点" | 探索共居、共享客厅与跨城市网络 |
| 扩展期 | 2018起 | 通过生活实验室、串门计划延伸至多城市 | 上海、广州、成都、武汉、深圳等 |
| 全球化 | 疫情后 | 轻量、可复制的全球节点建设 | 城市客厅与"空房子"等短周期空间实验 |
| 当下 | 2026 | 松散但持续运作的跨城市网络 | 不依附某一座城市，作为社区方法被实践 |

### 2.2 社区本质

706 不再依附于某一座城市，而是作为一种以**公共性、自组织与生活实验**为核心的社区方法，在不同文化与城市语境中被不断实践、调整与重启。

**青年空间（Youth Space）定义**：
- 介于公共机构与私人场所之间的城市中介空间
- 面向青年群体的学习、交流与自我组织需求
- 强调低门槛进入、非正式学习、同辈互动与公共讨论
- 为青年在城市中的社会化过程提供实验性与过渡性的支持结构

## 3. "六共"价值观体系

706 相信，在高度原子化与被效率裹挟的城市生活中，"在一起"本身是一种正在消失的公共能力。

### 3.1 六大核心价值观

| 价值观 | 核心定义 | 实践要点 | 常见误区 |
|--------|---------|---------|---------|
| **共居** | 把日常生活重新变成可共同协商、承担的过程 | 真实相处而非功能拼接；共享时间空间资源同时尊重个体边界 | ≠ 简单的"住在一起" |
| **共享** | 对空间、知识、关系与机会的开放使用权 | 降低进入门槛；对公共资源的自觉维护；形成公共物品 | ≠ 平台式的资源占用 |
| **共学** | 为学习提供发生的条件，而非教学 | 通过对话、共读、实践与经验交换；非功利、非评估环境 | ≠ 教学或培训 |
| **共玩** | 被认真对待的生活方式 | 通过游戏、创作、即兴与玩笑，重新激活信任与想象力 | ≠ 逃避现实的娱乐 |
| **共建** | 空间不是"被提供"的，而是被参与者共同塑造的 | 制定规则、维护秩序、解决冲突、面对失败 | ≠ 义务劳动 |
| **共创** | 所有实践的延伸形态，不预设成果 | 在开放协作中让新的关系、项目与表达自然生成 | ≠ 追求规模复制 |

### 3.2 价值观实践原则

```
公共性优先 → 降低参与门槛 → 让陌生人安全相遇、真实交流
    ↓
尊重个体差异 → 允许来去自由 → 接受不确定与失败
    ↓
空间视为持续迭代的社会实验 → 而非消费景观
    ↓
不以流量和产出为唯一目标 → 保留不完全被交换价值主导的生活方式
```

## 4. 个人/团队成长六阶段模型

706 不把成长简单理解为职位晋升、技能培训或个人曝光，而是把它放在真实的公共协作中。

### 4.1 成长路径

```
开放进入 → 轻量参与 → 真实贡献 → 信任积累 → 角色升级 → 经验沉淀
   ↓           ↓           ↓           ↓           ↓           ↓
 了解社区    不需长期承诺   完成具体事务   持续行动    获得资源权限   转化为团队能力
```

### 4.2 各阶段详解

| 阶段 | 核心动作 | 关键标志 | 设计要点 |
|------|---------|---------|---------|
| **开放进入** | 了解社区正在发生什么、参与方式、规则边界 | 新人能找到公开入口 | 提供社区介绍、项目说明、活动入口与协作资料 |
| **轻量参与** | 参加活动、协助现场、整理资料、认领小任务 | 双方在真实行动中相互了解 | 不需要一开始就长期承诺；找到适合自己的投入节奏 |
| **真实贡献** | 独立负责一次活动、一份内容、一个社区任务 | 对结果、沟通与复盘承担完整责任 | 成长不是"进了多少群"，而是完成过什么具体事务 |
| **信任积累** | 按时回应、兑现承诺、尊重边界、处理分歧 | 持续行动建立的信用 | 信任不来自身份、资历或亲疏，而来自持续行动 |
| **角色升级** | 成为项目负责人、节点协调者、公共岗位成员 | 获得更多资源与决策权 | 也承担更高的公开责任 |
| **经验沉淀** | 复盘、交接、模板整理、公开归档 | 个人经验转化为团队能力 | 使后来者可以接续工作，不同城市能够复用方法 |

> **Gotcha**：成长路径不是线性的"升级打怪"。一个人可能在"轻量参与"阶段就做出了极高价值的贡献，也可能在"角色升级"后仍需要回到基础任务。关键是持续行动和真实承担。

## 5. 组织架构设计

### 5.1 分布式社区结构

706 的组织构成本质上是"**节点自治 + 支持中心协同 + 节点大会共识决策 + 轻量治理维护规则**"的分布式社区结构。

```
                    ┌─────────────┐
                    │  节点大会    │  ← 跨节点公共协商机制
                    │ (共识决策)   │     信息交流、提案讨论、投票
                    └──────┬──────┘
                           │
            ┌──────────────┼──────────────┐
            │              │              │
     ┌──────┴──────┐ ┌────┴─────┐ ┌──────┴──────┐
     │  治理小组    │ │ 支持中心  │ │ 公共支撑机制  │
     │ (规则/秩序)  │ │ (服务枢纽)│ │ (财务/理事会) │
     └──────┬──────┘ └────┬─────┘ └──────┬──────┘
            │              │              │
            └──────────────┼──────────────┘
                           │
                    ┌──────┴──────┐
                    │  社区项目    │  ← 实际行动与资源流转
                    │ (公共/商业)  │     公共项目发起、商业项目孵化
                    └─────────────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
        ┌─────┴──┐  ┌─────┴──┐  ┌─────┴──┐
        │ 节点 A  │  │ 节点 B  │  │ 节点 C  │  ← 最基础的组织单元
        │(城市客厅)│ │(生活实验室)│ │(流动客厅)│     自发发起和维护
        └────────┘  └────────┘  └────────┘
```

### 5.2 六大组织单元

| 单元 | 定位 | 核心职责 | 关键特征 |
|------|------|---------|---------|
| **706节点** | 最基础的组织单元 | 在地活动、空间和成员关系 | 先有节点生长，再有大会/治理/支持围绕节点展开 |
| **节点大会** | 公共协商机制 | 跨节点信息交流、提案讨论、共同决策和投票 | 不取代节点本身，让分散节点形成共识 |
| **治理小组** | 规则、秩序和争议处理 | 社区边界、行为规范、争议处理、例外应对 | 不是"管理层"，是维护社区长期运转条件的机制 |
| **支持中心** | 服务与协同枢纽 | 节点接入、运营支持、技术支持、行政协助 | 更偏执行和服务，让节点和项目跑起来 |
| **公共支撑机制** | 制度化安排 | 财务小组（资源使用/透明机制）、理事会（重大事项/长期价值） | 把资源、责任、公共协调连接起来 |
| **社区项目** | 实际行动 | 公共项目发起、商业项目孵化、社区成果转化 | 从组织关系走向实际行动和资源流转 |

### 5.3 "小中心、大网络"原则

```
小中心                          大网络
  │                               │
  ├─ 维护跨节点协调               ├─ 城市节点负责在地活动
  ├─ 维护知识体系                 ├─ 项目团队围绕具体目标自主协作
  ├─ 维护公共基金                 ├─ 各节点没有行政隶属关系
  ├─ 维护传播工具                 └─ 基于共同价值与规则形成去中心化网络
  └─ 维护基础规则
```

> **Gotcha**：706 不是先有一个中心再去分派地方执行，而是先有节点不断生长、行动和连接，后续的大会、治理、支持与项目机制，都是围绕节点展开的。

## 6. 三种节点形态

### 6.1 节点类型对比

| 维度 | 城市客厅 | 流动客厅 | 生活实验室 |
|------|---------|---------|-----------|
| **空间形态** | 实体场所 | 无固定地点 | 持续实践场域 |
| **时间性** | 稳定持续 | 临时短期 | 中长期 |
| **核心载体** | 对话、共学、共创、日常相处 | 沙龙、共居、短期驻留、公共讨论 | 共居、共学、共创 |
| **本质** | 开放、平等的公共氛围 | 通过人的连接让"客厅"流动 | 探索新型生活方式的实践 |
| **适用场景** | 城市中有固定空间的社区 | 跨城市或资源有限时 | 深度生活实验和协作 |

### 6.2 节点建设要点

**城市客厅建设**：
- 核心不在于空间本身，而在于营造开放、平等的公共氛围
- 让陌生人能够自由进入、停留与交流
- 通过对话、共学、共创和日常相处，让陌生人形成连接与信任

**流动客厅建设**：
- 不依赖固定空间，通过人的连接与共同参与
- 让"客厅"的公共氛围在不同城市之间流动与延续
- 适合资源有限或跨城市探索阶段

**生活实验室建设**：
- 不是单纯的居住空间，也不是活动场地
- 是一种持续的实践过程：人们共同生活、讨论与创造
- 在实践中检验关于社区、协作与公共生活的各种可能性

### 6.3 节点自治原则

- 各节点之间没有行政隶属关系
- 共享的不是统一模板，而是基本的公共原则
- 保持可进入的社区入口
- 尊重差异、公开重要信息
- 承担在地责任
- 愿意将经验反馈给更大的社区网络

> **Gotcha**：706 不是一个复制同一种空间的连锁体系，而是一张能够容纳不同生活方式与在地实践的社区网络。北京、上海、广州、成都、清迈、柏林、纽约等城市，拥有不同的社会环境、成员结构、文化语境与资源条件。

## 7. 社区治理机制

### 7.1 治理核心原则

706 把**公共性、开放参与、成员保护与长期信任**放在社区治理的核心位置。

| 原则 | 说明 |
|------|------|
| **不靠个人信用运行** | 社区不依靠少数人的个人信用或临时热情运行 |
| **清晰的角色与分层决策** | 通过清晰角色、分层决策、公开记录、责任授权和反馈机制 |
| **治理目标不是增加控制** | 而是在保持开放性的同时，保护社区成员、公共资金、品牌、数据、空间和知识资产 |
| **重要事务可参与、可解释、可追溯** | 让规则能够在实践中持续修订 |

### 7.2 权限逻辑

```
贡献 → 信任 → 责任 → 权限

• 贡献应被记录和确认，但不能直接兑换永久权力
• 成员只有在承担明确责任时，才获得相匹配的发布、管理、资产或代表权限
• 职责结束后相关权限也应完成交接与回收
```

### 7.3 公共边界

**必须进入公开、可记录程序的事项**：
- 公共资金
- 公共岗位
- 品牌
- 空间
- 数据
- 商业合作
- 社区信任

**不进入普通调解的事项**（优先保护成员、及时止损）：
- 骚扰
- 暴力
- 财务安全
- 重大隐私泄露
- 持续伤害

### 7.4 反馈、问责与修订

```
反馈入口 → 记录保留 → 利益回避复核 → 处理结果 → 公示与复盘
    ↓           ↓           ↓           ↓           ↓
 清晰的      涉及公共岗位  与事项不存在   闭环处理    规则持续
 投诉渠道    资金使用等    直接利益关系   + 改进     修订完善
            保留记录      的人员参与               的人员参与复核
```

### 7.5 公共基金管理

```
申请 → 评审 → 拨付 → 执行 → 公示 → 复盘
                                    ↓
                            异常支出/利益冲突/重大风险
                                    ↓
                            进入更高层级的公共讨论
```

> **Gotcha**：规则不是一次制定后永久不变，而应通过成员反馈、案例复盘和书面修订不断完善。治理小组存在的意义是让 706 保持公共性和可持续性，而不是去替代节点做日常运营。

## 8. 社区活动组织流程

### 8.1 全流程 SOP

```
真实问题/兴趣/共同需求
        ↓
   发起人提出想法
   说明：讨论什么？适合谁？需要什么支持？
        ↓
   社区伙伴共同完善
   完善主题、流程和参与方式
        ↓
   活动前准备
   • 706提供空间连接、宣传发布、报名工具
   • 根据规模分配：接待、签到、布场、主持、摄影、记录
        ↓
   活动开始
   • 向参与者介绍活动目的、空间规则和互动方式
   • 让第一次来的人也能知道如何参与
        ↓
   活动进行
   • 简短自我介绍或破冰
   • 主题分享/共同体验/小组讨论
   • 主持人帮助问题展开、照顾节奏、让不同声音表达
   • 允许提问、分歧、沉默和临时生成的新话题
        ↓
   活动结束
   • 不要求所有人形成一致结论
   • 整理照片、讨论纪要、参与者反馈和后续行动
        ↓
   经验沉淀
   • 把一次现场经验沉淀为案例、工具或下一次活动的起点
```

### 8.2 活动氛围设计

| 要素 | 说明 |
|------|------|
| **开放轻松** | 没有严格的身份区分，嘉宾、组织者与参与者都可以进入真实交流 |
| **安全被听见** | 好的活动不一定热闹，而是让参与者感到安全、被听见 |
| **允许不成熟** | 可以带着尚未成熟的想法出现，可以承认不知道答案 |
| **不要求一致** | 允许提问、分歧、沉默和临时生成的新话题 |
| **持续连接** | 很多新的读书会、项目合作、城市行动和长期关系，都从一次普通的活动开始 |

## 9. 社区知识库建设

### 9.1 知识库定位

706 希望把分散在活动、空间、项目与成员经验中的知识，整理成可以被持续查找、使用和共同维护的公共资源。

**三个核心原则**：

| 原则 | 说明 |
|------|------|
| **每个人都能共学** | 知识不只来自专家和课程；空间主理人、活动组织者、志愿者、研究者、开发者和普通参与者都可能拥有值得分享的经验 |
| **从实践中学习** | 知识不是脱离行动的抽象总结，而是在真实实践中形成的 |
| **保留过程与失败** | 知识库不仅保存结果，也记录过程、问题与失败经验，帮助后来者减少重复劳动 |

### 9.2 知识库内容类型

```
一篇文章     → 把个人经验转化为社区共同使用的知识
一次访谈     → 记录真实经历和洞察
一个案例     → 完整记录从想法到执行的全过程
一份书单     → 共学主题的参考资源
一个工具包   → 可复用的操作模板
一份活动记录 → 现场经验和参与者反馈
一个项目复盘 → 分工、筹资、执行和改进的完整记录
```

### 9.3 案例沉淀模板

```markdown
# [活动/项目名称] 案例归档

## 1. 背景
- 发起原因（什么真实问题/兴趣/需求？）
- 目标参与者
- 空间与协作需求

## 2. 议题设计
- 主题选择理由
- 讨论框架
- 邀请方式

## 3. 执行过程
- 时间线
- 主持流程
- 现场分工（接待/签到/布场/主持/摄影/记录）

## 4. 现场问题
- 遇到的挑战
- 临时调整
- 参与者反应

## 5. 参与者反馈
- 正面反馈
- 改进建议
- 后续行动意向

## 6. 改进建议
- 下一次可以怎么做
- 可复用的模板/工具
- 需要注意的坑
```

> **Gotcha**：当经验只存在于少数人的记忆里，人员离开，能力也会一起消失。知识库要做的，是让每一次真实实践都成为后来者可以继续使用的公共起点。

## 10. 包容性与多元共生

### 10.1 核心理念

706 相信，**差异不是需要被抹平的问题，而是社区保持开放、活力与创造力的重要来源**。

### 10.2 包容性设计要点

| 维度 | 做法 | 避免的误区 |
|------|------|-----------|
| **平等进入** | 公开渠道说明活动、项目、任务信息 | 不依赖熟人关系或身份标签 |
| **多元节点** | 各城市共享基本公共原则，不共享统一模板 | 不把某节点做法视为整个社区的统一规则 |
| **轻量参与** | 提供不需要长期承诺的入口 | 不要求新人先成为"核心成员" |
| **不同意见** | 让不同意见能够被表达、听见和讨论 | 不要求所有人保持一致 |
| **反馈渠道** | 提供建议、投诉、冲突调解和申诉入口 | 不让冲突只在私下处理 |
| **真实行动** | 在真实行动中相互了解 | 不依赖关系介绍或身份标签 |

### 10.3 降低隐性门槛

```
熟人关系门槛 → 通过公开信息入口降低
身份资历门槛 → 通过轻量参与入口降低
表达能力门槛 → 通过主持人照顾节奏降低
信息差门槛  → 通过公开渠道说明降低
```

> **Gotcha**：真正的包容，不是要求所有人保持一致，而是让不同意见能够被表达、听见和讨论。706 希望形成的不是一个没有冲突的同温层，而是一个能够承接差异、处理冲突，并在共同实践中持续修正自身的公共社区。

## 11. 场景脚本

### 场景一：从零建立城市节点

**用户**："我想在自己的城市建立一个 706 风格的社区节点，怎么开始？"

**执行步骤**：
1. **明确节点定位**：城市客厅（有固定空间）/ 流动客厅（无固定空间）/ 生活实验室（深度共居实验）
2. **找到初始成员**：从真实问题出发，找到有相似底层的人——不是关于组织要什么，而是这里的一个个个体想要什么
3. **建立公共入口**：公开说明社区在做什么、有哪些参与方式、规则和边界
4. **组织第一场活动**：从真实问题/兴趣出发，邀请人讨论，不追求复杂包装
5. **建立轻量参与机制**：新人可以先参加活动、协助现场、认领小任务
6. **积累信任**：通过持续行动（按时回应、兑现承诺、尊重边界）建立信任
7. **经验沉淀**：复盘、交接、模板整理，让后来者可以接续工作
8. **连接更大网络**：将经验反馈给更大的社区网络

### 场景二：社区冲突处理

**用户**："我们社区出现了成员之间的冲突，怎么处理？"

**执行步骤**：
1. **判断冲突性质**：是意见分歧（进入公共议事）还是涉及骚扰/暴力/财务安全（优先保护成员、及时止损）
2. **提供反馈入口**：让当事方有清晰的投诉和申诉渠道
3. **记录保留**：涉及公共岗位、资金使用、权限滥用的问题保留必要记录
4. **利益回避复核**：由与事项不存在直接利益关系的人员参与复核
5. **公共议事**：帮助社区讨论公共问题、形成决定并留下说明
6. **复盘与规则修订**：通过案例复盘完善规则，避免类似问题再次发生

### 场景三：设计社区成长路径

**用户**："我们想让社区成员有清晰的成长路径，怎么设计？"

**执行步骤**：
1. **开放进入**：提供公开的社区介绍、项目说明、活动入口与协作资料
2. **轻量参与**：设计不需要长期承诺的小任务入口
3. **真实贡献**：让成员独立负责具体事务（活动、内容、任务、流程）
4. **信任积累**：建立基于持续行动（非身份资历）的信任机制
5. **角色升级**：稳定贡献后可成为项目负责人、节点协调者
6. **经验沉淀**：通过复盘、交接、模板整理把个人经验转化为团队能力

## 13. 风险提示

| 风险 | 说明 | 应对 |
|------|------|------|
| 熟人关系封闭 | 社区变成小圈子，新人难以进入 | 公开信息入口、轻量参与入口、不依赖关系介绍 |
| 个人信用依赖 | 社区运作依赖少数人的个人信用 | 建立清晰角色、分层决策、公开记录机制 |
| 规则僵化 | 规则一次制定后永久不变 | 通过成员反馈、案例复盘和书面修订持续完善 |
| 空间消费化 | 空间变成消费景观而非公共实验 | 保持公共性优先、降低参与门槛 |
| 经验流失 | 人员离开后能力消失 | 知识库建设、经验沉淀为公共资源 |
| 冲突失控 | 不同意见无法被处理 | 提供反馈、调解和申诉渠道；区分意见分歧与安全事件 |
| 统一模板化 | 强制所有节点采用相同模式 | 共享基本公共原则，允许在地差异化 |
| 商业化侵蚀 | 商业项目侵蚀社区公共性 | 公共项目与商业项目分路径管理；公共基金闭环管理 |
